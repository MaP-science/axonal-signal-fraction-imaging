# Data and pretrained-model provenance

Recorded on 2026-11-24. The Apache-2.0 grant for project-original source code
does not license the arrays, input datasets, generated training datasets, or
pretrained model/scaler artifacts described here. Their status is set out
separately below. This separation does not impose new terms on third-party
material or determine whether upstream data terms apply to a trained model.

## `directions_325_l_24.npy`

- Repository path: `asfimaging/shtools/data/directions_325_l_24.npy`.
- Shape and dtype: `(325, 3)`, `float64`.
- SHA-256: `5f1105826114cb3afeb334baade69390fef33f6cab35a7bc2dcf591cf5582d87`.
- Use: directions at which the relaxed spherical-harmonic positivity constraint
  is enforced, for both real-data and synthetic fits.
- Source: generated by the project maintainer with
  [qspace](https://github.com/ecaruyer/qspace) (Emmanuel Caruyer; Revised BSD
  license), which computes near-uniform point sets on the sphere by
  electrostatic-repulsion optimisation, treating antipodal points as
  equivalent. Generation parameters, qspace version and date: not recorded.
- Citation requested by qspace for use of its sampling tool:
  Caruyer E, Lenglet C, Sapiro G, Deriche R. Design of multishell sampling schemes with uniform coverage in diffusion MRI. Magn Reson Med. 2013;69(6):1534-1540. doi:10.1002/mrm.24736.
- Properties checked on 2026-11-24: unit vectors; no duplicates; not
  antipodally symmetric (each direction also constrains its antipode for the
  even-order SH fits used here); minimum angular separation 7.7°; maximum
  absolute sphere average of real SH up to degree 24 below 2e-3 (near-uniform,
  not an exact spherical design). It does not match any direction array
  shipped with DIPY 1.11.0.
- License: project-original material under the project's Apache-2.0 license.
  The array is output generated with qspace and contains no qspace source
  code; qspace's license covers its software and disclaims warranty for the
  sampling schemes it generates, without placing terms on them.

This is a spherical direction set, not an HCP participant-derived ODF array.
It replaces `directions724.npy` (DIPY `repulsion724` vertices), which earlier
versions used and which is no longer distributed.

## `odf_checked.npy`

- Repository path: `asfimaging/sh_descoteaux/odf_checked.npy`.
- Shape and dtype: `(476650, 91)`, `float32`.
- SHA-256: `9cabea7e120520d7c18676690aa9ee463f67de22aeacf3419dc72a60b442fcf0`.
- Provenance supplied by the project maintainer: curated and modified ODFs
  obtained by fitting multi-shell multi-tissue constrained spherical
  deconvolution (MSMT-CSD) to one MGH Adult Diffusion HCP dataset.
- Source collection: MGH-USC HCP Adult Diffusion, not WU-Minn HCP.
- Subject identifier, exact download/release, acquisition of access, accepted
  agreement version, fitting software/version, fitting parameters, curation
  operations, and processing dates: unknown/not available from the maintainer.

The shape and hash are independently verified. The source and processing
description above are maintainer-provided and cannot currently be reproduced
from a subject-specific processing record. The 91 columns are consistent with
an even spherical-harmonic basis through order 12; that observation does not
establish the original fitting settings or coefficient convention.

The repository's generator loads an ODF array from its configuration, retains
positive zeroth coefficients, truncates to 91 coefficients, normalizes them,
filters by spherical variance, and samples variance bins. Those are current
training-time operations, not verified descriptions of the historical
curation that produced this file.

### Data terms and acknowledgment

The collection has a separate MGH-USC agreement. Consult the agreement actually
accepted when obtaining the source data and the accompanying data-use
application; neither is available in this repository. References checked on
2026-11-24:

- [MGH Adult Diffusion acquisition and access documentation](https://www.humanconnectome.org/study/hcp-young-adult/document/mgh-adult-diffusion-data-acquisition-details)
- [MGH-USC HCP Data Agreement](https://www.humanconnectome.org/storage/app/media/documentation/mgh_diffusion/HCP_Data_Agreement.pdf)
- [MGH-USC acknowledgment and citation instructions](https://www.humanconnectome.org/study/hcp-young-adult/document/hcp-citations-mgh-usc-consortium)

The posted agreement limits disclosure to the approved uses and application,
requires recipients to comply, and requires acknowledgment. It is not an
unconditional Apache-2.0 data grant. This repository makes no independent
grant of redistribution rights for `odf_checked.npy`.

The maintainer's selected approach is to provide code and training instructions
without pretrained models, while retaining this ODF collection with the
[accompanying data-use notice](asfimaging/sh_descoteaux/odf_checked.npy.README.md).
Users training with it should review the MGH-USC agreement and confirm the terms
applicable to their intended use, including commercial use and redistribution
of the ODFs, simulated data, or trained models. Institutional or data-custodian
clarification may be needed. Do not substitute the WU-Minn agreement or
acknowledgment.

Retaining the file and adding a notice do not establish public redistribution
permission or override the agreement. The unresolved provenance and permission
status recorded above remain unchanged.

For publications and releases, use the MGH-USC acknowledgment wording at the
linked citation page and cite the relevant acquisition/data-release methods,
including Fan et al., *MGH-USC Human Connectome Project datasets with ultra-high
b-value diffusion MRI* (2016), where appropriate.

## Pretrained random forest models: separate licensing decision

Maintainer-reported training lineage:

`MGH Adult Diffusion data -> MSMT-CSD -> curated/modified ODFs -> simulated training signals -> random forest model`

Simulation does not by itself establish that upstream data-use obligations
cease to apply. The posted MGH-USC agreement does not explicitly classify
trained model parameters or authorize an unrestricted model release.
Whether model artifacts fall within its disclosure provisions remains
unresolved; this document does not assert that every trained model is legally
equivalent to its training data.

The selected distribution approach excludes pretrained models and provides
training code/instructions so users can train with appropriately authorized
inputs. The bundled ODF collection is retained with its separate data-use
notice; users can instead supply other documented ODF inputs.
No pretrained `.pkl` files were found in the working tree during this review.
Model parameters, fitted scalers, and generated training arrays are not granted
Apache-2.0 rights by the source-code license. No separate model license is
selected here.

Before a pretrained-model release:

1. Recover the source access agreement/application if possible, and ask the
   institutional data/contract office or MGH-USC custodian whether public
   redistribution of the ODFs, simulated arrays, model parameters, and scaler
   is permitted. Ask separately whether unrestricted commercial reuse and
   redistribution can be authorized for the models.
2. Record that determination, the model/artifact hashes, software versions,
   training configuration, validation, and known provenance gaps in a model
   card. Review the exported files for participant-derived records or metadata.
   Simulation or privacy checks alone do not establish redistribution rights.
3. If unrestricted model redistribution is confirmed, make an explicit model
   licensing decision with the rights holders; Apache-2.0 is a candidate to
   assess, not an automatic consequence of the code license.
4. If access or use conditions must carry through, distribute models only
   through an approved mechanism under the appropriate separate terms. Do not
   label a restricted model release as unqualified Apache-2.0.
5. If the necessary model-release permissions/provenance cannot be established,
   continue providing code and training instructions without pretrained models,
   or retrain using fully documented inputs that permit the intended model
   release. The retained ODF collection continues to have the separate status
   described above; it is not automatically cleared for redistribution.

These steps are release recommendations based on incomplete provenance, not
new restrictions on the Apache-2.0 source code or a legal determination about
ownership of model parameters. No data custodian has been contacted as part
of this repository update.
